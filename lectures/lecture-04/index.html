Bash scripts and their inputs

The shebang selects an interpreter when an executable script runs directly. Positional arguments such as $1 supply inputs. Quotes preserve spaces inside an argument.

#!/bin/bash
NAME=${1:-student}
echo "Running script $0"
echo "Good morning, $NAME!"
bash greetings.sh "Mr. Miller"
chmod +x greetings.sh
./greetings.sh "Mr. Miller"

Download greetings.sh

A child process receives exported variables. A variable assignment alone does not export a newly created variable.

export PET="Rhesus Monkey"
bash pets.sh

PATH and quoting

The shell searches the directories in PATH in order when a command name has no slash. Use $HOME inside quotes to refer to your home directory.

export PATH="$HOME/scripts:$PATH"
command -v greetings.sh

For interactive Bash, a persistent setting often belongs in ~/.bashrc. Bash login shells read a profile file instead, which may source that file. Interactive Zsh reads ~/.zshrc. A quoted "~/scripts" keeps the tilde literal in both shells. See the Bash startup rules and tilde expansion rules.

Data and output

CSV and TSV store rows and columns. JSON also represents nested objects and arrays. Use a format-aware parser when fields can contain delimiters or quotes.

command > output.txt       # replace stdout file contents
command >> output.txt      # append stdout
command 2> errors.log      # redirect stderr
command | next_command    # stdout becomes the next stdin

Check the activity to see why an error can still appear in the terminal when stdout goes to a file.

Control flow and failures

if [[ -f "data.txt" ]]; then
    echo "File exists"
else
    echo "File does not exist"
fi

names=("Alice Smith" "Bob")
for name in "${names[@]}"; do
    echo "$name"
done

Zero exit status means success. A nonzero status describes another outcome according to that command. && runs the next command on success. || runs it on failure.

set -euo pipefail

This enables useful failure checks. It still requires deliberate error handling: -e has exceptions in conditions, AND/OR lists, and other contexts. With pipefail, a pipeline reports its rightmost nonzero status, or zero if every command succeeds. See the Bash set builtin.

Python scripting

Python supports arguments, environment variables, files, structured parsing, logging, and exit codes. argparse adds named arguments, validation, and help. The example below cleans a small CSV file using Python's standard library.

python3 clean_data.py people.csv --output cleaned.csv
  • Download clean_data.py
  • Download people.csv (synthetic classroom data)

The script strips whitespace, removes empty names and duplicates, then writes a clean CSV. It logs progress to stderr. See argparse, csv, and Python logging.

Python project environments

Each project can keep its own installed packages. Project metadata declares dependencies. A lock file records resolved versions. These files support reproducibility when committed with the code.

uv init --no-package my_project
cd my_project
uv add requests pandas
uv run main.py

--no-package explicitly chooses a simple application layout. Use --package for a packaged project with a src/ layout. Defaults can differ between uv versions. uv add resolves dependencies and creates or updates the environment and lock file. See uv project creation and locking and syncing.

uv venv .venv
source .venv/bin/activate
uv pip install -r requirements.txt

The alternative above creates an environment without scaffolding a full project. A requirements file can list direct dependencies or a full set of pinned packages. It is a different format from uv.lock.
