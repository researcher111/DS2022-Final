Storage, databases, and data models

Storage holds bytes. A database management system (DBMS) adds a data model, queries, constraints, and coordinated access. Its query processor and storage engine work with both records and metadata describing their structure.

File storage exposes files and directories; block storage exposes addressable blocks; object storage exposes objects through an API. A DBMS can build on different storage systems. Relational databases organize related tables. Other models include documents, key-value pairs, wide-column records, and graphs.

Vertical scaling adds resources to a machine. Horizontal scaling distributes work across machines. These choices depend on the engine and workload: SQL does not imply vertical-only scaling, and NoSQL does not imply an absence of schemas or types. See distributed relational SQL and DynamoDB’s data model.

Schema, keys, and views

A schema describes tables, fields, types, and constraints. A primary key identifies a row; it can contain multiple columns. A foreign key constrains a reference to another table. Child rows may share the same referenced key. A required foreign key also needs NOT NULL.

The restaurant has two people named Alice: employee 1 lives in Michigan, and employee 3 lives in Wyoming. Their different IDs keep their identities separate. Use the ID to update one employee.

A regular view stores a query definition and exposes the query’s result. Changing the underlying tables can change that result. Object-relational mapping (ORM) libraries help map application objects to relational records; the schema and database constraints still matter. See MySQL table constraints, foreign keys, and views.

The restaurant’s normalization steps

  1. 1NF: Give each employee/job assignment its own row. A list such as “Chef, Waiter” contains multiple jobs. The assignment key is the pair (employee_id, job_code).
  2. 2NF: Separate facts that depend on only part of that pair. Employee names depend on employee ID; job labels depend on job code. Keep the assignments in a junction table.
  3. 3NF: Store state names in a states table. An employee records a state code, and that code determines the state’s name.

These rules describe the functional dependencies in this example. Normalization reduces repeated facts and update anomalies. It does not guarantee faster queries: joins, indexes, and workload affect performance. Denormalization can make selected reads cheaper while requiring a way to keep repeated facts consistent.

employees(employee_id, name, state_code)
states(state_code, home_state)
jobs(job_code, job)
employee_jobs(employee_id, job_code)

Queries and CRUD

The browser playground uses SQLite. The downloadable server examples below use MySQL. Both support the core queries here, but their setup commands, types, and some transaction details differ. SQLite uses PRAGMA table_info(employees) where the MySQL lesson uses DESCRIBE employees; it does not use MySQL’s CREATE DATABASE and USE. The activity enables SQLite foreign keys. See SQLite foreign keys and SQLite differences.

SELECT employee_id, name, state_code
FROM employees
WHERE name = 'Alice'
ORDER BY employee_id;

This query returns both Alices. WHERE selects rows, while the SELECT list chooses output columns. Parentheses make combined AND/OR conditions clear. Use IS NULL to test missing values, and ORDER BY when the order matters.

SELECT e.employee_id, e.name, j.job
FROM employees AS e
JOIN employee_jobs AS ej ON ej.employee_id = e.employee_id
JOIN jobs AS j ON j.job_code = ej.job_code
ORDER BY e.employee_id, j.job_code;

A join matches rows using its condition. Employee 1 has two assignments, so this result contains two rows for that employee.

  • INSERT creates a row, SELECT reads rows, UPDATE changes rows, and DELETE removes rows.
  • CREATE TABLE defines structure; DROP TABLE removes the table itself.
  • LIMIT caps the number of returned rows. Pair it with a deterministic ORDER BY to identify which rows.

Transactions and ACID

A transaction groups changes. A transfer should debit one account and credit the other together. Atomicity means all of those changes commit or none do. Consistency concerns declared constraints and application rules. Isolation controls what concurrent transactions can observe. Durability means successful commits persist according to the database’s guarantees.

START TRANSACTION;
UPDATE employees SET state_code = 56 WHERE employee_id = 1;
SELECT * FROM employees WHERE employee_id = 1;
ROLLBACK;

This MySQL example previews and undoes a change. Use COMMIT to keep it. A statement error does not necessarily undo earlier statements; handle failure with an explicit rollback. MySQL DDL can implicitly commit, so keep CREATE and DROP outside this rollback exercise. See transaction statements and implicit commits.

MySQL and Python

With uv installed, create an environment and install the connector. These commands use Bash/Zsh on macOS, Linux, or WSL:

uv venv --python 3.11
source .venv/bin/activate
uv pip install mysql-connector-python

Use your course’s connection details to set DB_HOST, DB_USER, DB_PASSWORD, and DB_NAME in your environment. The sample reads those values rather than storing credentials in the file. The default classic MySQL port is 3306; set DB_PORT if your server uses another port.

cursor.execute(
    "SELECT employee_id, name FROM employees WHERE state_code = %s",
    (56,),
)

Pass values separately from SQL. The connector binds the %s placeholder; Python string interpolation is not needed. A one-element tuple needs its trailing comma. Use conn.commit() after successful writes and conn.rollback() on failure. Closing the cursor or connection does not commit. See parameter binding and commit behavior.

JSON, Python, and SQL

The ETL activity extracts records from JSON, trims names and normalizes states, then inserts accepted rows with bound parameters. Invalid rows and repeated IDs within the batch are reported. Loading a batch happens in one transaction; a conflict with an existing database ID rolls back that load.

Try the downloadable version with Python’s built-in SQLite support. Save these two files in the same folder:

  • etl_sqlite.pyValidate and load a local database
  • employees.jsonSynthetic valid, duplicate, and malformed rows
python3 etl_sqlite.py employees.json --database lecture05.sqlite

The sample accepts Cara and O’Neil and reports three skipped rows. Rerunning against the same file reports duplicate database IDs and rolls back that batch. Select a new database filename to start fresh. SQLite’s Python placeholders are ?, unlike MySQL Connector’s %s. See Python’s SQLite API.

Cloud connections and recovery

A client needs a reachable hostname and port, credentials, and access to the intended database. Managed services also handle parts of operation, such as backups and maintenance. Amazon Aurora provides MySQL/PostgreSQL compatibility as a managed service; compatibility is distinct from an open-source license. See Aurora’s service overview and MySQL ports.

A network failure can prevent application access even while stored data remains intact. Recovery can produce a backlog of work. The lecture separates reachability, database state, and recovery load. Follow the course’s current AWS or HPC instructions for access; the source deck’s setup paths refer to externally maintained course material.
